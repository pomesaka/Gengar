# 要求定義

Claude Code のメトリクス収集ツール「Gengar」に対する要求を整理する。

## 1. 背景と目的

Claude Code の利用が進む中で「どのツールがどれだけ使われているか」「セッションあたりのコスト／トークン消費量はどの程度か」「どこで時間がかかっているか」といった情報を体系的に把握する手段が乏しい。結果として以下の問題が発生している。

- 利用パターンの可視化ができず、改善ポイントが分からない
- 高コストなパターン（無駄なリトライ、冗長なツール呼び出し）に気付きにくい
- Claude Code 自身が過去の実行傾向を参照できず、自己改善ループを回せない

本ツールは、Claude Code 実行時に得られる各種シグナル（hooks、セッション JSONL など）を横断的に収集・可視化・クエリ可能にすることで、これらの課題を解消することを目的とする。

## 2. ステークホルダー

| ステークホルダー | 関心事 |
|-----------------|--------|
| 開発者（Claude Code ユーザー） | 自分の使い方を把握したい／コストを抑えたい／生産性を上げたい |
| Claude Code 自身 | 過去の実行傾向をクエリし、より良い作業方針を立てたい |
| チーム / 組織（将来拡張） | チーム横断の利用傾向・コストを把握したい（初期スコープ外） |

## 3. 要求一覧

### R1. 多様なメトリクスの収集

- **R1.1** Claude Code の hook 機構（`PreToolUse` / `PostToolUse` / `UserPromptSubmit` / `Stop` / `SubagentStop` / `SessionStart` / `SessionEnd` / `Notification` / `PreCompact` など）を通じてイベントをリアルタイムに取得できること
- **R1.2** セッションごとに `~/.claude/projects/<project>/*.jsonl` に保存されるトランスクリプトを取り込み、hook で取り逃した**メタデータ**（トークン使用量、モデル、ツール呼び出しの種類・回数など）を補完できること。**本文（プロンプト／応答／ツール結果の生テキスト）は取り込まない**
- **R1.3** プロジェクトを問わず、ローカルで発生した全 Claude Code セッションを対象にできること
- **R1.4** 取得済みデータに対して、後からメトリクスを再計算・再集計できること
- **R1.5** すべてのレコード（イベント・集計）に **`session_id` ラベル**を付与し、ユーザーが必要に応じて `~/.claude/projects` 配下の JSONL を直接参照して本文を確認できること。Gengar 本体は本文を保持しない。

### R2. ダッシュボードでの可視化

- **R2.1** 収集したメトリクスをブラウザから閲覧できること
- **R2.2** セッション単位／プロジェクト単位／期間単位などの切り口で確認できること
- **R2.3** 典型的な関心事（総コスト、トークン消費量、ツール使用頻度、エラー率、所要時間など）をデフォルトで可視化すること
- **R2.4** ローカル環境で完結して動作し、外部送信を行わないこと

### R3. Claude Code からの集計アクセス（自己改善）

- **R3.1** Claude Code が MCP サーバー経由でメトリクスをクエリできること
- **R3.2** CLI からも同等の集計を取得できること（スクリプト・CI 連携を想定）
- **R3.3** クエリ結果は、Claude Code が文脈として取り込みやすい構造（JSON または簡潔なテキストサマリ）で返せること
- **R3.4** 自己改善に有用な典型クエリ（「直近セッションで最も失敗したツール」「平均的に何ターンで完了するか」「高コストだったセッション上位N件」など）をプリセットとして用意すること

### R4. データライフサイクル管理

- **R4.1 遡及取り込み（バックフィル）**: 過去の `~/.claude/projects/**/*.jsonl` を取り込むのは **明示的なユーザー操作 (CLI オプション) による場合に限る**。既定では導入以降のイベントのみを対象とする。取り込み範囲は期間指定 (例: `30d`, `all`) を選択できること。
- **R4.2 保持期間**: 生イベントの保持期間は **ユーザー設定で変更可能**とし、既定値は 90 日とする。`0` を指定した場合は無期限とする。
- **R4.3 ロールアップ長期保持**: 生イベントが保持期間を過ぎて削除された場合でも、**日次／週次ロールアップなどの集計値は無期限に保持**し、長期トレンドを閲覧可能にすること。
- **R4.4 個別削除**: ユーザーはセッション ID やプロジェクトパスを指定して、対応するイベント・集計データを**個別に削除できる**こと。機密情報が意図せず収集された場合の救済手段として要件化する。
- **R4.5 エクスポート（初期スコープ外）**: 一括エクスポート機能 (CSV / JSON) は Phase 1 ではスコープ外とする。必要な場合はユーザーが DB ファイルを直接コピー／SQL で取り出す前提とする。

## 4. 非機能要求

- **N1. ローカルファースト**: 収集データは原則ローカル（ファイルシステム／埋め込み DB）で完結する。クラウド送信は既定で無効。
- **N2. プライバシー**: Gengar は **純粋なメトリクス収集ツール** であり、プロンプト／アシスタント応答／ツール引数・結果の**生テキスト本文は一切保存しない**。保存対象は数値メトリクス・種別・タイムスタンプ・ID などメタデータに限る。本文の閲覧が必要な場合はユーザーが `~/.claude/projects` の JSONL を直接参照する前提とする（R1.5）。
- **N3. 軽量性**: hook 処理は Claude Code 本体の体感を阻害しない（個別 hook の処理時間は 50ms 以下を目標）。重い集計は非同期で行う。
- **N4. 堅牢性**: 収集プロセスが落ちても Claude Code の実行を妨げないこと（hook は非致命的に失敗する）。
- **N5. 拡張性**: メトリクス定義・ダッシュボードのビューを後から追加できる構造であること。
- **N6. 可搬性**: macOS / Linux で動作すること（Windows は努力目標）。

## 5. スコープ

> **基本方針**: 初期フェーズでは **Claude Code のみ** を対象とする。他の AI コーディングエージェント (Codex CLI / Cursor / Aider / Cline / Gemini CLI / Copilot 等) への対応は**初期フェーズではスコープ外**とし、Claude Code 向けの価値を出し切った後に改めて検討する。

### 5.1 初期フェーズのスコープ（Phase 1）

- **対象エージェント**: Claude Code のみ
- ローカル 1 ユーザー用のメトリクス収集・可視化・クエリ
- 情報源: `~/.claude` 配下（hooks 経由のイベント + プロジェクトごとの JSONL）
- hook インストール用の簡易セットアップコマンド
- MCP サーバー／CLI の両インターフェース
- Claude Code 特有のデータモデル（hook イベント種別、JSONL スキーマ、subagent、MCP ツール等）に最適化する

### 5.2 初期フェーズでスコープ外とするもの

**他エージェント対応（明示的に Phase 1 では扱わない）**

- Codex CLI / Cursor / Aider / Cline / Gemini CLI / GitHub Copilot CLI 等の取り込み
- エージェント横断のコスト統合ビュー
- エージェントを抽象化した共通データモデル

**その他**

- 複数ユーザー／チームでの集計・共有
- クラウド同期・SaaS 化
- 認証・権限管理
- 一括エクスポート機能 (CSV / JSON) — R4.5 参照

### 5.3 将来フェーズで検討（Phase 2 以降）

- 他エージェント対応（需要と Phase 1 の成果を踏まえて判断）
- チーム共有・クラウド同期
- 認証基盤

### 5.4 スコープ固定の含意

- データモデル・ストレージスキーマは Claude Code の形式に素直に合わせてよい（将来の抽象化に備えた過度な汎用化はしない）
- MCP ツール名・CLI サブコマンドも `claude` を前提とした命名を許容する
- ドキュメント・UI も Claude Code 用語 (session, hook, tool_use, subagent 等) をそのまま用いる

## 6. 成功指標

- セッション終了から 5 秒以内にダッシュボードで当該セッションの主要メトリクスを確認できる
- Claude Code から `/gengar` 相当のクエリを発行し、10 秒以内に集計結果を返せる
- 1,000 セッション／10 万イベント規模でもダッシュボードの主要ビューが 2 秒以内に表示される
